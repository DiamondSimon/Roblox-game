## Purchases and data risk

All three old Scrap product IDs are zero and storefront disabled in inspected source. Preserve hidden legacy definitions and numeric receipt migration; never repurpose a real product ID to a different reward. New receipts need currency-tagged amounts. Core cosmetic/quest claims must be durable and retry-safe; uncertain writes must not permit later overwrites or duplicate spending. Upgrade/inventory migration must preserve existing progress and capacity. Keep the existing store name; increment schema and reject future schemas. Do not reset existing accounts for economy tuning.

## Validation limitations

Add tests for daily rollover, replayed claims, insufficient funds, ownership, migrations, Core receipt retry, capacity preservation and movement caps. Model timings are assumptions, not observed retention. Studio phone and two-player tests remain required; never claim those have run here.
